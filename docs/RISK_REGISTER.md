# Risk register

Known risks of Prune, assessed on 2026-10-22 against the code of version 1.2.9. **Verified** means confirmed in the code or by a command; **assumption** means evidence is missing.

Severity × likelihood → priority (P1 first). Each risk links to a criterion in [RELEASE_CRITERIA.md](RELEASE_CRITERIA.md).

| ID | Risk | Evidence | Severity | Likel. | Priority | Mitigation | Criterion | State |
|---|---|---|---|---|---|---|---|---|
| R1 | The rules that decide what is junk (`SystemJunkScanner`, `PrivacyScanner`, `AppScanner.leftovers/orphans`) have no tests. The tests cover protection (`SafetyGuard`), but not what each scan selects. | Verified: no test calls these scanners; only the self-test runs them, read-only | High: a wrong rule preselects user data | Medium | **P1** | Extract the rules into functions that take the base folder; tests with a fake `~/Library` in `TempDir` | G2 | Open |
| R2 | `Cleaner.retryAsAdmin` checks the path with `SafetyGuard` and only then runs `rm -rf` / `mv` as root. If a parent folder is swapped for a symbolic link in the meantime, root deletes outside what was intended. | Verified in the code (`Cleaner.swift`) | High: deleting as root | Low: requires a malicious process already running as the user | **P1** | Pass the resolved path (`realpath`) to the script and refuse if any component is a link; check again inside the script | G3 | Open |
| R3 | No Developer ID or notarization: `spctl` rejects the app and the README says to run `xattr -dr com.apple.quarantine`, which gets people used to bypassing Gatekeeper. | Verified: `spctl -a -vv` → `rejected`; "Prune Local Signing" signature | Medium | High | **P2** | Apple Developer account (USD 99/year) with notarization in `ship.sh`; or accept the risk and document how to build from source | G5 | Open: maintainer decision (cost) |
| R4 | Privileged or destructive actions without a confirmation dialog: removing launch agents and daemons (as administrator, `rm -f`, permanent), removing extensions, and "Run" in the maintenance tasks (includes `tmutil thinlocalsnapshots`, which deletes local Time Machine snapshots, and `mdutil -E /`). | Verified: there is no `.confirm` in `OptimizationView`, `ExtensionsView` or `MaintenanceView`. So the README's "Nothing is deleted without confirmation" is not true today in these three sections | Medium/High | Medium | **P1** | Confirmation with what is going to happen; the daemon goes to the Trash instead of `rm -f` | G4 | Open |
| R5 | Caches and logs are deleted permanently by default, and no record is kept of what was deleted. | Verified: `junkDeleteMode` defaults to `.permanent` | Medium | Low (regenerable data) | P3 | Local log (on the Mac only) of what was deleted in each cleanup | G11 | Accepted for now |
| R6 | Compatibility was only verified on one machine (Apple silicon, with a macOS newer than the minimum). The Intel binary has never been run. | Verified: only local builds; CI is new in this version | Medium | Medium | **P2** | CI on macOS 14 and 15 (S3); manual test on Intel for each major | S3, section 6 | In progress: the first CI run found a build error with Xcode 16.2 / Swift 6.0 (macOS 14 runner), fixed in 1.3.1 |
| R7 | No signal from users: 3 downloads in total and no bug reports. With this, the 24 h soak is not evidence of stability. | Verified: Releases download counter | Medium | High | **P2** | Pilot programme before 2.0.0; issue templates for reporting bugs | G9 | Open |
| R8 | The Google Analytics API secret ships inside the distributed app's `Info.plist`. Anyone can extract it and send fake events. It gives no access to data. | Verified: `build_app.sh` injects it into `Info.plist` | Low | Medium | P4 | Inherent to the Measurement Protocol. Alternatives: an own proxy or removing telemetry | — | Accepted |
| R9 | Clearing Firefox history deletes rows from `places.sqlite` with `sqlite3`. | Verified. The list of browsers that must be closed exists; **assumption**: that it is always applied before this action | Medium: may corrupt the history | Low | P3 | Test with a sample database; confirm Firefox is closed immediately before | G2 | Open |
| R10 | The `main` branch is not protected on GitHub. The `pre-push` hook only protects from this machine; a merge done on the website bypasses everything. | Verified: the API returns "Branch not protected" | Medium | Medium | **P2** | Branch protection: Pull Request only, no force-push | G6 | Open: repository setting |
| R11 | There is no private way to report vulnerabilities. | Verified: `private-vulnerability-reporting` off | Medium | Low | **P2** | Turn it on in Settings ▸ Security; see [SECURITY.md](../SECURITY.md) | G7 | Open: repository setting |
| R12 | Non-reproducible builds: a single local compiler (Swift 6.3), with no record of the version in the Releases. | Verified | Low | Medium | P4 | Write the Swift and macOS versions used in the Release notes | — | Open |
| R13 | GitHub Actions pinned by major version (`@v4`), not by commit. | Verified in `.github/workflows/ci.yml` | Low | Low | P4 | Pin by SHA when there are external contributors | — | Accepted |
| R14 | Third-party dependencies | Verified: zero Swift packages; only Apple's toolchain and two GitHub actions | — | — | — | Keep it that way; any new dependency requires a review of its license (GPL-3.0-compatible) and maintenance | — | Controlled |
| R16 | Similar photos is not tested automatically on macOS 14: GitHub's macOS 14 runner cannot create a Vision inference context ("Could not create inference context"), so the test is skipped there and the coverage minimum for `DuplicateFinder.swift` drops from 85% to 80% on that machine only. | Verified: CI runs of 1.3.2 and 1.3.3; the skip and its reason are printed by `check.sh` | Medium: a regression on macOS 14 would not be caught by CI | Low: assumption that it is a limit of the virtual machine (it works on macOS 15 and on this Mac), not confirmed on physical macOS 14 hardware | P3 | Skip only for that exact error; any other Vision error still fails. Since 1.3.2 the app warns the user instead of showing "nothing found". Manual check on a physical macOS 14 Mac in each minor and major (section 6 of the criteria) | S3, section 6 | Accepted |
| R15 | An interface text without a translation shows in English to Portuguese users; a translation with different placeholders could show wrong values. | Verified: texts are looked up by key at runtime | Low | Medium | P4 | `scripts/check_localization.py` in `check.sh` (Q8) and Swift tests that load the Portuguese table | Q8 | Controlled (1.4.0) |

|---|---|---|---|

| R8 | Telemetry is optional (explicit consent) and only sends totals. The worst case is polluting the statistics. | 2026-10-22 | 2.0.0 |
| R13 | Single-maintainer project; the risk grows with external contributions. | 2026-10-22 | First external contributor |
| R16 | No macOS 14 runner with an inference context is available for free; the rest of macOS 14 stays tested, and similar photos is checked by hand on macOS 14 in each minor and major. | 2026-10-22 | When GitHub offers a macOS 14 runner with a GPU, or 2.0.0 |
