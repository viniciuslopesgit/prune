# Risk register

Known risks of Prune, assessed on 2026-10-22 against the code of version 1.2.9; R19–R22 come from the penetration test of 2026-10-23 (1.6.3), which `scripts/pentest.sh` now repeats in every check. **Verified** means confirmed in the code or by a command; **assumption** means evidence is missing.

Severity × likelihood → priority (P1 first). Each risk links to a criterion in [RELEASE_CRITERIA.md](RELEASE_CRITERIA.md).

| ID | Risk | Evidence | Severity | Likel. | Priority | Mitigation | Criterion | State |
|---|---|---|---|---|---|---|---|---|
| R1 | The rules that decide what is junk (`SystemJunkScanner`, `PrivacyScanner`, `AppScanner.leftovers/orphans`) have no tests. The tests cover protection (`SafetyGuard`), but not what each scan selects. | Verified: no test calls these scanners; only the self-test runs them, read-only | High: a wrong rule preselects user data | Medium | **P1** | Extract the rules into functions that take the base folder; tests with a fake `~/Library` in `TempDir` | G2 | Resolved (1.8.1): the scanners read the home folder through `ScanRoot`, which only tests change; `ScannerTests` and `ExtensionsTests` build a fake `~/Library` in `TempDir` and check what each scan offers and preselects (System Junk, Trash, Mail, Privacy, Uninstaller leftovers and orphans, browser extensions). Coverage minimums for these files are in `check.sh` |
| R2 | `Cleaner.retryAsAdmin` checks the path with `SafetyGuard` and only then runs `rm -rf` / `mv` as root. If a parent folder is swapped for a symbolic link in the meantime, root deletes outside what was intended. | Verified in the code (`Cleaner.swift`, up to 1.6.3); the pentest reproduces it by swapping the parent and the grandparent for links | High: deleting as root | Low: requires a malicious process already running as the user | **P1** | Since 1.6.4 `Cleaner.adminScript` resolves the parent with `realpath`, and each item runs in a subshell that enters it with `cd -P`, confirms it is still the checked folder and acts on `./name` (the shell holds the folder from then on). The Trash must be a real folder, not a link; `chown -h` | G3 | Fixed in 1.6.4 |
| R3 | No Developer ID or notarization: `spctl` rejects the app and the README says to run `xattr -dr com.apple.quarantine`, which gets people used to bypassing Gatekeeper. | Verified: `spctl -a -vv` → `rejected`; "Prune Local Signing" signature | Medium | High | **P2** | Apple Developer account (USD 99/year) with notarization in `ship.sh`; or accept the risk and document how to build from source | G5 | Open: maintainer decision (cost) |
| R4 | Privileged or destructive actions without a confirmation dialog: removing launch agents and daemons (as administrator, `rm -f`, permanent), removing extensions, and "Run" in the maintenance tasks (includes `tmutil thinlocalsnapshots`, which deletes local Time Machine snapshots, and `mdutil -E /`). | Verified: there is no `.confirm` in `OptimizationView`, `ExtensionsView` or `MaintenanceView`. So the README's "Nothing is deleted without confirmation" is not true today in these three sections | Medium/High | Medium | **P1** | Confirmation with what is going to happen; the daemon goes to the Trash instead of `rm -f` | G4 | Open |
| R5 | Caches and logs are deleted permanently by default, and no record is kept of what was deleted. | Verified: `junkDeleteMode` defaults to `.permanent` | Medium | Low (regenerable data) | P3 | Local log (on the Mac only) of what was deleted in each cleanup | G11 | Accepted for now |
| R6 | Compatibility was only verified on one machine (Apple silicon, with a macOS newer than the minimum). The Intel binary has never been run. | Verified: only local builds; CI is new in this version | Medium | Medium | **P2** | CI on macOS 14 and 15 (S3); manual test on Intel for each major | S3, section 6 | In progress: the first CI run found a build error with Xcode 16.2 / Swift 6.0 (macOS 14 runner), fixed in 1.3.1 |
| R7 | No signal from users: 3 downloads in total and no bug reports. With this, the 24 h soak is not evidence of stability. | Verified: Releases download counter | Medium | High | **P2** | Pilot programme before 2.0.0; issue templates for reporting bugs | G9 | Open |
| R8 | The Google Analytics API secret ships inside the distributed app's `Info.plist`. Anyone can extract it and send fake events. It gives no access to data. | Verified: `build_app.sh` injects it into `Info.plist` | Low | Medium | P4 | Inherent to the Measurement Protocol. Alternatives: an own proxy or removing telemetry | — | Accepted |
| R9 | Clearing Firefox history deletes rows from `places.sqlite` with `sqlite3`. | Verified. The list of browsers that must be closed exists; **assumption**: that it is always applied before this action | Medium: may corrupt the history | Low | P3 | Test with a sample database; confirm Firefox is closed immediately before | G2 | Open |
| R10 | The `main` branch is not protected on GitHub. The `pre-push` hook only protects from this machine; a merge done on the website bypasses everything. | Verified: the API returns "Branch not protected" | Medium | Medium | **P2** | Branch protection: Pull Request only, no force-push | G6 | Open: repository setting |
| R11 | There is no private way to report vulnerabilities. | Verified: `private-vulnerability-reporting` off | Medium | Low | **P2** | Turn it on in Settings ▸ Security; see [SECURITY.md](../SECURITY.md) | G7 | Open: repository setting |
| R12 | Non-reproducible builds: a single local compiler (Swift 6.3), with no record of the version in the Releases. | Verified | Low | Medium | P4 | Write the Swift and macOS versions used in the Release notes | — | Open |
| R13 | GitHub Actions pinned by major version (`@v4`), not by commit. | Verified in `.github/workflows/ci.yml` | Low | Low | P4 | Pin by SHA when there are external contributors | — | Accepted |
| R14 | Third-party dependencies | Verified: zero Swift packages; only Apple's toolchain and two GitHub actions | — | — | — | Keep it that way; any new dependency requires a review of its license (GPL-3.0-compatible) and maintenance | — | Controlled |
| R16 | Similar photos is not tested automatically on macOS 14: GitHub's macOS 14 runner cannot create a Vision inference context ("Could not create inference context"), so the test is skipped there and the coverage minimum for `DuplicateFinder.swift` drops from 85% to 80% on that machine only. | Verified: CI runs of 1.3.2 and 1.3.3; the skip and its reason are printed by `check.sh` | Medium: a regression on macOS 14 would not be caught by CI | Low: assumption that it is a limit of the virtual machine (it works on macOS 15 and on this Mac), not confirmed on physical macOS 14 hardware | P3 | Skip only for that exact error; any other Vision error still fails. Since 1.3.2 the app warns the user instead of showing "nothing found". Manual check on a physical macOS 14 Mac in each minor and major (section 6 of the criteria) | S3, section 6 | Accepted |
| R17 | On macOS 14, the self-test crashed (SIGTRAP in `_NSAssertMainEventQueueIsCurrentEventQueue`): it started its scans from `PruneApp.init`, and a background scan used AppKit before the main event queue existed. A race: under lldb, slower to start, it passed. | Verified: crash report and lldb runs of 1.4.5 on GitHub's macOS 14 runner | Medium: it hid whether the app works on macOS 14 | High on that runner | P2 | The diagnostic tools start from the main queue, once the run loop runs (1.4.6). Assumption: the app in normal use is not affected, because its scans only start after the interface is up; to confirm on a physical macOS 14 Mac (section 6 of the criteria) | S3 | Fixed in 1.4.6, to confirm in CI |
| R18 | Code scanning (CodeQL) alerts. **#2 `py/redos`** in `scripts/stable.py`: the regex that finds `### Fixed` took exponential time on many blank lines. **#1 `swift/path-injection`** in `SystemJunkScanner.brokenLaunchAgents`: the `Program` path read from a launch agent `.plist` reaches `fileExists`. | Verified: #2 took more than 5 min on 6,000 blank lines; #1: that path is only checked for existence, never opened, run or deleted; what can be removed is the `.plist` itself, which comes from the folder listing and goes through `SafetyGuard` and the confirmation | #2 Low (the input is our own CHANGELOG); #1 none | — | P4 | #2: regex with `[ \t]` instead of `\s`, and a test that 50,000 blank lines run in under 1 s (1.4.7). #1: dismiss as a false positive in GitHub, with this reason | — | #2 fixed in 1.4.7; #1 false positive |
| R19 | `SafetyGuard` compared paths letter by letter, but APFS and HFS+ are case-insensitive: `~/documents`, `/SYSTEM` or `~/library/keychains` passed the list and pointed at the real protected folders. Same for the folders ignored in Settings. | Verified by the pentest (`SecurityTests`): 8 attack tests failed against 1.6.3 | Critical: the whole Documents folder could be deleted | Low: the app's own lists use the right case; a path typed, dropped or built from another case could get through | **P1** | Since 1.6.4 paths are compared lowercased and with canonical Unicode composition (`SafetyGuard.key`) | G2 | Fixed in 1.6.4 |
| R20 | Shredder overwrote files with other hard links: the data of another name, possibly outside the chosen folder (a pnpm `node_modules` shares its files with the global store), was destroyed. It also opened the file following links, after checking it. | Verified by the pentest | High: destroys data the user did not choose | Low | **P2** | Since 1.6.4 the file is opened with `O_NOFOLLOW` and checked on the descriptor; a file with other hard links is not overwritten, only its name here is deleted | G2 | Fixed in 1.6.4 |
| R21 | Uninstaller: a leftover was any entry whose name *contained* the bundle ID. The ID comes from the app's own `Info.plist`: an app with the ID `e` or `com` preselected almost all of `~/Library` for deletion. | Verified by the pentest | High: preselects user data | Low: needs a malformed or malicious app | **P2** | Since 1.6.4 `AppScanner.isLeftover` requires a real bundle ID (two or more parts) and matches only whole dot-separated parts | G2 | Fixed in 1.6.4 |
| R22 | Updater: the download and "What's new" links of an appcast (from the network, sometimes over http) were opened with `NSWorkspace` whatever their scheme: `file://` or another app's URL scheme would open or run something local. | Verified by the pentest | Medium | Low: needs a hostile or intercepted appcast | P3 | Since 1.6.4 only `https` links with a host are kept (`UpdateService.webURL`) | — | Fixed in 1.6.4 |
| R23 | Since 1.8.0 the minimum is macOS 12, but GitHub has no macOS 12 (or 13) runners: on macOS 12 the app uses its own interface path (AppKit main window and menu bar, no Window/MenuBarExtra/NavigationSplitView/SMAppService), which hosted CI only runs on macOS 15 with `PRUNE_LEGACY_UI=1`. A macOS 12-only crash (an API that exists but behaves differently there) would not be caught. | Verified: the compiler rejects unguarded APIs newer than 12 (deployment target 12.0); `macos12.yml` checks `minos 12.0` on both architectures and runs the self-test with the macOS 12 interface. **Assumption**: that it behaves the same on a real macOS 12 | Medium: the app may not open on macOS 12 | Medium | **P2** | Self-hosted macOS 12 runner (`MACOS12_RUNNER=true`, label `macos-12`) in `macos12.yml`; until then, a manual launch on macOS 12 in each minor and major | S3, section 6 | Open: needs a Mac with macOS 12 as runner |
| R24 | A browser profile (Chromium `Default`, `Profile N`; Firefox profile) or a Firefox `places.sqlite` that is a symbolic link made Privacy offer files of the folder it points to, and run the history SQL on another database. | Verified by attack tests in `SecurityTests` against 1.8.0 | High: deletes files outside the browser's data | Low: needs a planted link in ~/Library | **P2** | Since 1.8.1 profiles and `places.sqlite` that are links are skipped (`FS.isLink`) | G2 | Resolved (1.8.1) |
| R25 | Browser extensions: the Firefox extension path came from `extensions.json` (anyone can write it in the profile) and "Remove" sent it to the Trash. Any folder could be listed as an extension; Chromium profiles and extension folders that are links had the same effect. | Verified by attack tests against 1.8.0 | High: moves any user folder to the Trash | Low: needs a modified profile | **P2** | Since 1.8.1 the path must be a direct child of the profile's own `extensions` folder (resolved), never a link (`BrowserExtensions.firefoxExtensionURL`) | G2 | Resolved (1.8.1) |
| R26 | `SafetyGuard` had two gaps found by fuzzing: it protected the contents of the prefix folders (`/private/var/db/`, `/usr/bin/`, `/Library/Apple/`…) but not the folders themselves, and it took the last path component from the original URL, so `/private/var/db/.` or `…/x/..` were checked as `/private/var/.`. | Verified: `safetyGuardFuzz` (3,000 deterministic variants) and `prefixFolderItself` failed against 1.8.0 | Critical: a protected system folder could reach the administrator retry | Low: needs such a path to reach the cleaner | **P2** | Since 1.8.1 prefixes also protect the folder itself and both checks use the standardized URL; the fuzz test runs in every check and in the sandbox | G2 | Resolved (1.8.1) |
| R27 | The release binary kept an rpath into the build machine's toolchain (`/Applications/Xcode.app/…/swift-6.2/macosx`). The app loads nothing through `@rpath` today, but such a path on a user's Mac is where a planted library could be loaded from. | Verified with `otool -l` on 1.8.0 | Medium | Low | P3 | Since 1.8.1 `build_app.sh` removes every rpath but `/usr/lib/swift`, and `scripts/security_audit.sh` fails on any other | G2 | Resolved (1.8.1) |
| R28 | No hardened runtime and no notarization: the app is signed without `--options runtime`, so the system does not enforce library validation or block debugger attachment by other processes of the same user. | Verified: `codesign -dvv` shows `flags=0x0` | Medium | Low | P3 | Enable the hardened runtime with the Apple Events entitlement it needs (login items, AppleScript), tested by hand; ideally together with R3 (Developer ID) | G2 | Open |
| R15 | An interface text without a translation shows in English to Portuguese users; a translation with different placeholders could show wrong values. | Verified: texts are looked up by key at runtime | Low | Medium | P4 | `scripts/check_localization.py` in `check.sh` (Q8) and Swift tests that load the Portuguese table | Q8 | Controlled (1.4.0) |
